Ein Bildschirm zum Steuern, einer für die Spieler.

Ich habe lib/main.dart (2.500 Zeilen) und main.js durchgesehen. Die App funktioniert und sieht schon gut aus. Die größten Hebel sind: Spieleranzeige auf einen zweiten Bildschirm auslagern, das Timer-Panel auf den Live-Betrieb reduzieren und ein paar Bugs bei Sync, Speichern und Löschen beheben.

Was mir im Code aufgefallen ist

Sortiert nach Auswirkung im Turnierbetrieb. Zeilennummern beziehen sich auf lib/main.dart, außer anders angegeben.

Bug

Ungespeicherte Eingaben werden bei „Next Round“ überschrieben

Textfelder werden erst mit „Apply“ übernommen. nextRound() und loadPreset() rufen _syncTextFields() auf. Wer z. B. schon Siegernamen oder einen neuen Eventnamen getippt hat und dann „Next Round“ drückt, verliert die Eingabe ohne Hinweis. Dropdowns und der Logo-Schalter speichern dagegen sofort. Das ist inkonsistent.

Sync

Zwei Fenster schreiben gleichzeitig denselben Zustand

Im #player-Modus lädt das Fenster jede Sekunde aus SharedPreferences. Bei 00:00 speichert es aber auch selbst (_setStateModel im Ticker). Drückt die Turnierleitung genau dann „+5 Min“, kann das Spielerfenster die Änderung überschreiben. Die Anzeige läuft außerdem bis zu 1 s hinterher. Besser: nur das Control Panel schreibt, die Anzeige liest per BroadcastChannel bzw. Electron-IPC.

Timer

Sekunden können springen oder hängen

Timer.periodic(1s) ist nicht an die Sekundengrenze gekoppelt, und remainingNow rundet mit floor(). Dadurch springt die Anzeige gelegentlich 10:00 → 09:58. Mit einem 200–250 ms-Tick, einer festen endsAt-Zeit statt remainingSeconds + lastUpdate und ceil() läuft es sauber.

Das Dropdown im Timer-Panel hat eine fest kodierte Liste statt gameOptions. Steht in den gespeicherten Daten ein Spiel, das nicht in der Liste ist, wirft Flutter einen Assertion-Fehler. Der Preset-Editor fängt das ab, das Timer-Panel nicht.

6 · Technik

So kommt der Timer auf den zweiten Bildschirm

Der Flutter-Code kann schon einen reinen Anzeige-Modus (#player in der URL). Es fehlt vor allem die Electron-Seite und ein schnellerer Sync.

Fenster 1 · Control PanelPrimärer Bildschirm. Einzige Stelle, die den Zustand ändert und speichert.
BroadcastChannel
oder Electron-IPC
Fenster 2 · Spieleranzeige/#/player, Vollbild auf dem externen Bildschirm, rahmenlos, nur lesend.
Electron main.jsErkennt Bildschirme mit screen.getAllDisplays(), öffnet Fenster 2 auf dem externen Bildschirm, merkt sich die Wahl, reagiert auf An-/Abstecken. Ohne zweiten Bildschirm bleibt der heutige Vollbild-Modus als Fallback. Im Browser geht dasselbe per window.open('/#/player') bzw. Window Management API.
// main.js – Skizze
const { app, BrowserWindow, screen, ipcMain } = require('electron');

function openPlayerWindow(displayId) {
  const displays = screen.getAllDisplays();
  const target = displays.find(d => d.id === displayId)
    ?? displays.find(d => d.id !== screen.getPrimaryDisplay().id);
  if (!target) return null; // kein 2. Bildschirm → Fallback: Vollbild im Hauptfenster

  const win = new BrowserWindow({
    ...target.bounds, frame: false, fullscreen: true, backgroundColor: '#06101F',
    webPreferences: { contextIsolation: true, preload: path.join(__dirname, 'preload.js') },
  });
  win.loadURL(`http://127.0.0.1:${PORT}/#/player`);
  return win;
}

screen.on('display-added',   () => mainWin.webContents.send('displays-changed'));
screen.on('display-removed', () => mainWin.webContents.send('displays-changed'));
ipcMain.handle('player:open', (_e, id) => !!openPlayerWindow(id));
